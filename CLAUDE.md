## Project state

`iron_heritage` is an early-stage Flutter app. The only application code is the
flavor scaffolding generated by `flutter_flavorizr` (`lib/main.dart`,
`lib/app.dart`, `lib/flavors.dart`, `lib/pages/my_home_page.dart`). There is no
state management, routing, networking, or persistence layer yet — treat those
structural decisions as open, and don't assume conventions exist that aren't in
the code.

`.freezed.dart` / `.g.dart` parts go stale and analysis fails.

## Flavors

The app has two flavors, **`dev`** and **`prod`**, wired by `flutter_flavorizr`.

**A flavor is mandatory on every run and build** — bare `flutter run` fails with
a missing-flavor error now that product flavors exist:

```bash
flutter run --flavor dev              # dev on a device/emulator
flutter run --flavor prod
flutter build apk --flavor prod       # Play upload artifact
flutter build appbundle --flavor prod
```

| Flavor | Application ID | Display name |
|---|---|---|
| `dev` | `com.pedroremedios.ironheritage.dev` | Iron Heritage Dev |
| `prod` | `com.pedroremedios.ironheritage` | Iron Heritage |

Distinct application IDs mean dev and prod install side by side on one device.
In debug builds `App` draws a corner banner naming the active flavor.

`F.appFlavor` (in `lib/flavors.dart`) is `late final` and set once in `main()`
from Flutter's built-in `appFlavor` constant, which comes from
`package:flutter/services.dart` — that import in `main.dart` looks unused but is
load-bearing; do not remove it. Widget tests must assign `F.appFlavor`
themselves before pumping `App`, since no `--flavor` argument exists under test.

### Changing flavors

Edit the `flavorizr:` block in `pubspec.yaml`, then re-run:

```bash
dart run flutter_flavorizr -f        # -f skips the interactive confirm
```

This **rewrites native files in place** — `android/app/build.gradle.kts`,
`android/app/flavorizr.gradle.kts`, the Xcode `project.pbxproj`, xcconfigs,
schemes, `Info.plist` — and **overwrites `lib/main.dart`, `lib/app.dart`, and
`lib/pages/`**. Commit before running it, and expect to reapply any hand edits
made to those Dart files. Adding a flavor is a clean re-run; removing one leaves
native leftovers.

Application IDs are immutable once an artifact is uploaded to Google Play. Do
not change the `prod` ID after the first upload.

## Constraints to respect

- **Platforms: Android and iOS only.** Only `android/` and `ios/` exist.
  `flutter run -d chrome` (or windows/macos/linux) fails until the platform is
  added via `flutter create --platforms=<p> .`.
- **Do not lower `sdk: ^3.12.2`** in `pubspec.yaml`. Flutter 3.44 / Dart 3.12 is
  the toolchain this is verified against.
- Lints come from `package:flutter_lints/flutter.yaml` with no project overrides
  in `analysis_options.yaml`.
- Generated `.freezed.dart` / `.g.dart` files are **committed**, not gitignored.
  Keep them regenerated and in the commit rather than adding ignore rules.

## Code generation (freezed)

Data classes use [freezed](https://pub.dev/packages/freezed) with
`json_serializable`.

> **Version note:** `freezed` is pinned to **exactly `3.2.5`** (stable) — no
> prereleases, deliberately. `dart pub add dev:freezed` will resolve to the
> `4.0.0-dev.x` line, because freezed 3.0-3.2.0 caps `source_gen` at ^2/^3 while
> `json_serializable ^6.14.0` needs ^4.1.2. Do not accept that resolution:
> 3.2.5 satisfies both (`source_gen 4.2.3`) at the cost of holding `analyzer` at
> 10.2.0 instead of 13.x. Revisit only when freezed 4.0 ships stable.

Two syntax gotchas — most snippets online are 2.x and will not compile here:

- Freezed 3.x/4.x requires **`abstract class`** (or `sealed class` for unions).
  Plain `class Foo with _$Foo` is a 2.x pattern and fails to generate.
- This project's `build_runner` has **removed `--delete-conflicting-outputs`**;
  passing it prints `These options have been removed and were ignored`. Just run
  `dart run build_runner build`.

Verified working shape:

```dart
import 'package:freezed_annotation/freezed_annotation.dart';

part 'my_model.freezed.dart';
part 'my_model.g.dart';   // only if the class needs fromJson/toJson

@freezed
abstract class MyModel with _$MyModel {
  const factory MyModel({
    required String name,
    @Default(0) int count,
  }) = _MyModel;

  factory MyModel.fromJson(Map<String, dynamic> json) => _$MyModelFromJson(json);
}
```
